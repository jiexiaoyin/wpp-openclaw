# WPP 脱敏豁免清单 (2026-09-27 审阅加固)
#
# 用途: 声明「某些文件里的敏感形态串是**测试样本/必需输入**, 不该被替换, 也不该拦下提交」。
#
# 为什么需要它 (根因):
#   脱敏器原先只有「替换」和「只查」两种模式, **无法表达豁免**。
#   而 tests/unit/sanitize-rules.test.mjs 是**脱敏器自己的测试** —— 它必须用
#   真实形态的串 (群 ID/手机号) 作输入, 才能验证「真实形态确实会被替换」。
#   没有豁免机制 ⇒ 该文件永远命中 ⇒ 门永远红 ⇒ 有人会习惯性 --no-verify ⇒ **门就废了**。
#   豁免机制的价值不在「放行」, 在「让门保持可信」。
#
# 本文件**不含任何敏感串** (只有路径与理由) ⇒ 可安全入仓、可随发布分发。
# 敏感串仍只在 ~/.openclaw/wpp-sanitize.rules (dev-only, 0600, 绝不入库)。
#
# 格式 (一行一条, "glob<TAB>理由"):
#   <glob 模式>\t<豁免理由>
#   - glob 相对仓库根; ** 匹配任意层级; * 匹配单层内任意字符
#   - # 开头为注释; 空行忽略
#   - 匹配到的文件: --check 跳过 / --apply 跳过 / --check-history 同样跳过
#   - ⚠️ 豁免请写**最小范围**(具体文件路径), 不要用宽泛目录 —— 豁免越宽, 门越弱
